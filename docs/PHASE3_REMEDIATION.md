## Completed changes

**Medium — misleading semantic passes: corrected and gated.** Benchmark `demo-quality-v3` requires a separate structured local-Qwen assessment of answer meaning in addition to the existing fact/source/quote checks. The judge compares the candidate with canonical SQL policy text and expected behavior. Missing, invalid, uncertain, contradicted or unsupported assessments cannot produce an automated pass. A model error produces a failed run and releases the inference slot. Assessment reasons and fingerprints are saved and exported. Prompt `quality-v1/semantic_review.txt` is versioned separately; answer-generation prompts are unchanged.

The constructed answer that previously passed despite negating the expense-policy duties is now rejected as contradicted. The local challenge also rejects swapped duties, a false approval threshold, the wrong entitlement period, a fabricated receipt exception, unsupported contractor entitlement, an invented CEO inside an apparent abstention, and attempts to instruct the judge. Four faithful answers, including qualified scope and genuine abstention, pass. This is evidence for those cases, not a universal hallucination guarantee.

**Medium — confusing automated checks with acceptance: corrected.** The UI shows each automated semantic verdict and reason, with a direct **Read source policy** action opening the full authorized document. Even a complete automated pass remains `needs_human_review`; explicit correct judgments for every case are required for `reviewed_correct`. Incorrect/uncertain judgments, failed automatic checks and incomplete/failed runs cannot receive that sign-off. No automated tool writes human judgments. Historical results are labeled as having no semantic assessment, and their original scores remain historical.

**Medium — pending backend activation: completed.** The normal stop script verified and stopped the prior process, a verified snapshot was taken, and the current app was started hidden on loopback. Process changed from **62140 to 53032**. Health reports **ready** with build **68a72e6f7d486da6**, independently matched to current source/prompt bytes. The four earlier medium fixes are active, not merely present on disk. Runtime evidence (local artifact `phase3-remediation-runtime.json`).

**Recovery recommendation: implemented and rehearsed.** `scripts.backup` refuses active vector stores, unfinished work, nested snapshots and overwrite restores. It snapshots SQL under a write lock, copies vectors under their storage lock, checks all file hashes and SQL integrity, and restores only to a new directory with old login sessions removed. Verification itself does not mutate the snapshot. Tests caught and corrected a snapshot-verification WAL side effect before use on actual data. A real snapshot was restored into a temporary directory; all 13 documents, 26 chunks, four users, six tickets, two reports, five approvals, 96 workflows, three historical evaluations and one feedback record were preserved. Persisted vector IDs/payloads matched SQL and vector queries worked. The original active store was not replaced. Rehearsal evidence (local artifact `phase3-recovery-rehearsal.json`).

**Reproducibility recommendation: implemented.** Both installed Ollama model digests and the semantic prompt hash are recorded. Context validation checks these values before/after inference as well as the existing source/prompt/current-role checks. Runtime health exposes a build fingerprint captured at startup. Tags alone are no longer the only model identity in new benchmark records.

**Pilot planning and source review: delivered.** The [operations and pilot runbook](OPERATIONS_RUNBOOK.md) supplies backup/restore and manual retention procedures, a human semantic-review rubric, and explicit identity, source ownership, recovery, capacity and connector responsibilities. SSO/cloud deployment/external integrations were not added to this local MVP. Actual independent policy-owner review still requires a person; its counters are not fabricated.
